Guia Detalhado — Git & GitHub

Conceitos, fluxos de trabalho e resolução de conflitos explicados em profundidade

Conceitos Fundamentais de Git & GitHub

O Git é um sistema de controle de versão distribuído. Isso significa que cada desenvolvedor tem uma cópia completa do repositório, incluindo o histórico, no seu computador. Com isso, é possível trabalhar offline, criar experimentos em branches e integrar mudanças de forma colaborativa.

Principais Conceitos

  • Commit: uma foto do seu código em determinado momento. Exemplo: feat: adiciona página inicial.
  • Branch: uma ramificação do projeto para desenvolver algo novo sem atrapalhar a versão estável.
  • Merge: processo de unir mudanças de duas branches.
  • Rebase: reaplica commits em cima de outra base, mantendo histórico linear.
  • Remote: repositório hospedado em um servidor (GitHub, GitLab, Bitbucket).

GitHub

O GitHub é uma plataforma que hospeda repositórios Git. Ele adiciona recursos de colaboração como Pull Requests, Code Review, Issues e GitHub Pages (para deploy de sites estáticos). 

# inicializa repositório e primeiro commit
git init
git add .
git commit -m "feat: inicia projeto"

# cria e troca para uma nova branch de feature
git checkout -b feat/pagina-inicial

# trabalha, comita…
git add index.html
git commit -m "feat(home): estrutura inicial da página"

Fluxos de Trabalho

Um fluxo define como a equipe organiza suas branches e integra mudanças, evitando caos no histórico e garantindo qualidade do código.

GitHub Flow (Simples)

  1. main sempre estável.
  2. Criar branch para cada tarefa: feat/nova-funcionalidade.
  3. Após desenvolvimento, abrir Pull Request para main.
  4. Passa por revisão e testes.
  5. Merge e deploy.
Fluxo indicado para projetos menores, com integração contínua.

Git Flow (com Develop)

Usado em times maiores. As branches principais são:

  • main: produção.
  • develop: integração de features.
  • feat/*: novas funcionalidades.

No final, develop é mesclada na main para gerar uma versão.

# parte de main atualizada
git checkout main
git pull origin main

# cria branch da tarefa
git checkout -b feat/login

# commits…
git add .
git commit -m "feat(login): tela e validações"

# publica no remoto e cria PR
git push -u origin feat/login
# abrir o PR no GitHub e pedir review

Resolução de Conflitos

Conflitos acontecem quando duas branches modificam a mesma linha de um arquivo. O Git pede que o desenvolvedor escolha qual versão manter.

Exemplo de Conflito

<<<<<<< HEAD
console.log("Olá da sua branch");
=======
console.log("Olá da branch que veio do merge");
>>>>>>> develop

Após resolver:

console.log("Olá final");

Passo a Passo

  1. git status para ver arquivos em conflito.
  2. Abrir arquivos e localizar <<<<<<<, =======, >>>>>>>.
  3. Escolher/mesclar versões.
  4. Apagar marcadores e salvar.
  5. git add arquivo.
  6. git commit (merge) ou git rebase --continue.

Dicas

  • Fazer git pull frequentemente.
  • Commits pequenos e focados.
  • Usar ferramentas visuais (VS Code, GitKraken, Sourcetree).
# durante um merge:
git status
code app.js
git add app.js
git commit

# durante um rebase:
git rebase main
# resolver conflitos…
git add app.js
git rebase --continue

Pull Requests

Pull Request é uma solicitação para mesclar uma branch em outra, permitindo revisão, testes e discussões.

Checklist

  • Título claro: feat(login): adiciona autenticação.
  • Descrição do que foi feito e por quê.
  • Testes locais realizados.
  • Sem arquivos irrelevantes.
# publicar branch
git push -u origin feat/login

# opção 1: abrir PR no site do GitHub
# opção 2: usando GitHub CLI
gh pr create --base main --head feat/login \
  --title "feat(login): autenticação" \
  --body "Descrição do que foi feito."

Deploy com GitHub Pages

Após integrar na main, é possível publicar sua página HTML gratuitamente:

  1. No repositório: Settings > Pages.
  2. Selecionar Deploy from a branch.
  3. Escolher branch main e pasta /.
  4. URL: https://usuario.github.io/repositorio/.
# cria página inicial
echo "<!doctype html><title>Olá Mundo</title><h1>Site no GitHub Pages</h1>" > index.html

git add index.html
git commit -m "chore: adiciona página inicial"
git push origin main
# depois configurar Settings > Pages

Passo a Passo Final

Guia rápido para aplicar o fluxo completo com Git e GitHub:

  1. Entrar no projeto:
cd nome-projeto
  1. Checar branches locais e remotas:
git branch      # locais
git branch -a   # remotas
  1. Entrar na branch desejada:
git checkout nome-da-branch
  1. Atualizar a branch:
git pull origin nome-da-branch
  1. Criar nova feature:
git checkout -b feature/nome-da-nova-feature
  1. Fazer alterações e subir modificações:
git add .
git commit -m "explicando o que alterei"
git push origin nome-da-feature
  1. Abrir Pull Request no GitHub:
  • Ir em Pull requests → New pull request.
  • base: branch destino (ex.: main).
  • compare: sua branch de feature.
  • Criar PR.
  1. Fazer o merge:
  • Clicar em Merge pull request.
  • Confirmar em Confirm merge.
  • (Opcional) Delete branch.
